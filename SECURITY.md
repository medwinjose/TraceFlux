# Security Policy

## TraceFlux Prototype Security Considerations

**TraceFlux is a hackathon-grade prototype and is NOT designed for production deployment in its current state.**

It was built to demonstrate real-time fraud propagation and behavioral ML scoring concepts. The following security implementations are simulated and intentionally bypass standard enterprise security practices for the sake of demo simplicity.

### 1. Cryptography and Key Management
- **HMAC Signatures**: The HMAC keys found in `backend/security.py` are for demonstration purposes to show tamper-evident log concepts. They must **never** be reused in a real deployment.
- **Production Requirement**: A production interdiction rail must use robust, environment-based secrets management (e.g., HashiCorp Vault, AWS KMS) with automated key rotation policies.

### 2. Authentication and Authorization
- **No API Auth**: Currently, there is zero authentication on the FastAPI endpoints or WebSocket hub. Anyone with network access to the demo instance can call `POST /report_fraud`, `POST /reset`, or listen to the WebSocket event stream.
- **Production Requirement**: All endpoints must require strict authentication (OAuth 2.0, API keys with RBAC) mapping to specific institutional identities.

### 3. Transport Security
- **No TLS**: The demo runs on standard HTTP/WS for easy local setup.
- **Production Requirement**: Both REST API and WebSocket connections must be secured via TLS 1.3 (HTTPS/WSS) at the edge proxy or load balancer.

### 4. Data Privacy
- **Synthetic Data**: The data generated by `backend/simulate.py` is entirely synthetic. No real-world PII, account data, or transaction history is processed or stored.
- **Production Requirement**: A live system requires stringent data anonymization, encryption at rest, and compliance with local privacy regulations (e.g., GDPR, DPDP Act) when handling real transaction streams.

## Reporting a Vulnerability
Because this is a public prototype repository with intentionally absent production security layers, please do not file CVEs or security advisories for the known missing features (Auth, TLS, Hardcoded Demo Keys) listed above.

If you find an issue in the *logic* of the BFS tag propagation engine or ML scorer that could cause severe false positives/negatives in a real-world adaptation, please open an issue in the repository.
